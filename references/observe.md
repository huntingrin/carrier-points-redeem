# 页面读取：一屏一读

> 只在需要写页面提取脚本时读本文件；不写脚本就不读。本文件是**加速手段**，不是必需步骤。
> 任何一档失败都退到下一档，业务判断不变：**读不到就补读一次，补读还不行就交给用户看屏幕。**

## 为什么要一屏一读

一次兑换的 agent 侧成本，主要不是网络，而是**同一屏被反复读**：
先看号码、再看积分、再看面额、再看规则，每看一次就是一次完整往返。

目标：**每个页面阶段只读一次，一次拿全该阶段要判断的字段。**

## 三档能力，按宿主降级

| 档 | 宿主能力 | 做法 | 成本 |
|---|---|---|---|
| A | 能执行页面脚本（Ego `page.evaluate`、CDP `Runtime.evaluate`、Playwright `evaluate` 等） | 用下面模板一次取全 | 1 次调用 |
| B | 只能读无障碍树/快照（`snapshot`、aria） | **一次**快照，按自上而下顺序读完号码、积分、面额、规则 | 1 次调用 |
| C | 只能截图 | 一次截图，只用于确认按钮位置和版面；**数字不靠截图读** | 1 次调用 |

B/C 档的关键不是"读得更快"，而是**不要为每个字段各截一次**。快照一次就够，缺字段再补一次。

## A 档模板：通用页面摘要

一次执行，返回结构化摘要。所有字段缺失时返回空数组或 null，**不抛错**，避免整段失败。

```js
(() => {
  const clean = (s) => (s || "").replace(/\u00a0/g, " ").replace(/[ \t]+/g, " ").trim();
  const uniq = (a) => [...new Set(a)];
  try {
    const raw = document.body ? document.body.innerText : "";
    const lines = raw.split("\n").map(clean).filter(Boolean);
    const grab = (re, n) => uniq((raw.match(re) || []).map(clean)).slice(0, n);
    const has = (re) => re.test(raw);
    return {
      url: location.href,
      title: clean(document.title),
      stage: has(/支付成功|兑换成功|充值成功|订单已完成|提交成功/) ? "success"
           : has(/确认支付|收银台|本单支付|待支付|立即支付/) ? "checkout"
           : has(/短信验证|验证码|获取短信/) ? "verify"
           : has(/登录|忘记密码|密码登录/) ? "login" : "browse",
      masked: grab(/1[3-9]\d\*{4}\d{4}/g, 4),
      balances: grab(/(?:可用|剩余|通信|奖励|专属|账户)?\s*(?:积分|AI\s*豆|豆)[：:\s]*\d{1,8}/g, 8),
      amounts: grab(/\d{1,5}(?:\.\d{1,2})?\s*元/g, 20),
      orderLines: lines.filter((l) => /订单|单号|编号|流水/.test(l)).slice(0, 8),
      rules: lines.filter((l) => /不退|不可退|仅限|限本机|当月|有效期|续订|到期|仅可/.test(l)).slice(0, 10),
      buttons: uniq(
        [...document.querySelectorAll("button,a,[role=button],input[type=submit],input[type=button]")]
          .map((e) => clean(e.innerText || e.value || e.getAttribute("aria-label") || ""))
          .filter((t) => t && t.length <= 20)
      ).slice(0, 20),
      text: lines.slice(0, 60).join(" | "),
    };
  } catch (e) {
    return { error: String(e), url: location.href };
  }
})()
```

使用要点：

- 返回的 `text` 已经压成单行，**用它替代整页快照**；不要同时再取快照。
- `stage` 只用来判断"我现在在哪一步"，不代替子技能里的页面阶段判断。
- 字段为空不等于 0：`balances` 空说明"还没读到"，必须等信号或补读一次，**不要当成余额 0**。
- 这是通用摘要，不绑定任何运营商的选择器。页面改版、跨省差异都不影响它，最坏情况是字段变少。

## 每个阶段要拿到的字段

| 阶段 | 必须拿到 | 拿到后就能做的判断 |
|---|---|---|
| 登录页 | `stage=login`、是否已有登录态、`masked` | 要不要交接给用户 |
| 商城/专区 | `masked`、`balances`、`amounts` | 账户对不对、够不够兑、有哪些面额 |
| 确认页/结算 | 订单号、商品名、积分、现金、接收号码 | 能不能提交 |
| 验证页 | `stage=verify`、要用户做什么 | 交接，不读验证码 |
| 成功页/订单页 | 订单号、状态、扣分 | 只读对账，不再点击 |

**同一阶段第二次读取前问自己：第一次缺的是哪个字段？** 只补那个字段，不要整页再读一遍。

## 等待：等信号，不等时间

- 用宿主的条件等待（`waitForSelector` / `waitForFunction` / 轮询条件但只在宿主侧执行），超时 5–15 秒。
- **不要** `sleep(3) → 截图 → sleep(3) → 截图`。这是本项目最容易放大轮次的地方。
- 超时后读一次页面：如果还是占位（0、空列表、"加载中"），再等一次；两次都没有就以"未加载"为准，不要一直等，也不要当成真实 0。

## 导航、等待、读取合成一次

打开一个新页面时，不要拆成"导航一次、等待一次、读一次"——三次调用就是三轮。能在一个脚本里做完就一次做完：

```js
// 按宿主 API 改写；关键是合并，不是照抄。
await page.goto(URL, { waitUntil: "domcontentloaded" });
await page.waitForFunction(
  () => /积分|AI\s*豆|登录|验证码|订单/.test(document.body ? document.body.innerText : ""),
  { timeout: 15000 }
).catch(() => {});          // 超时不要抛，继续读，由字段是否为空决定下一步
return await page.evaluate(/* 上面的摘要模板 */);
```

超时被吞掉不是失败，只是"没等到信号"：摘要里字段为空就按"未加载"处理，不要立刻重来一遍。

## 交接：一条消息说清

把本轮用户要做的**全部动作**写进同一条消息，而不是一步步挤牙膏：

> 需要你在当前页面完成：① 输入手机号 ② 点"获取短信"并填入验证码 ③ 点"登录"。
> 这是第一次登录，之后这个浏览器会记住；完成后回我一句"好了"，我接着核对账户和面额。

不要在交接消息里索要验证码，不要让用户把验证码发到聊天里。也不要在这条消息里问"你用哪个浏览器"——用宿主能驱动的那个，或者用户已经开着的那个。

## 反例

| 反例 | 代价 |
|---|---|
| 每读一个数字截一次图 | 5–8 次多余往返，token 暴涨 |
| 用 `sleep` 循环等页面加载 | 轮次翻倍，还容易读到占位 0 |
| 全页快照后再补一次全页快照 | 上一屏的内容重复进上下文 |
| 把页面 `text` 全文粘进回复 | 用户看不懂，且下一轮又读一遍 |
| 交接时分三条消息问 | 每问一次多一轮 |

## 降级判定

```
A 档失败（脚本被禁/报错）
  → B 档：一次快照
    → 字段仍不全
      → 补读一次（只补缺的字段）
        → 仍不全：停下，说明"页面没读到 X"，让用户看屏幕确认
```

**任何一档都不得跳过业务校验**：账户不一致要停、现金不为 0 要停、状态不明不重复提交。速度永远排在这些之后。
