# 浏览器与登录态

> 只在两种情况下读本文件：宿主没有可用的浏览器工具；或第一次导航失败、判断不了登录态。
> 宿主自带浏览器自动化时，正常路径不需要读。

## 一、按能力选路径，不要让用户改环境

| 档 | 宿主能力 | 怎么做 | 第一次 | 之后 |
|---|---|---|---|---|
| T1 | 能驱动浏览器（自带引擎、CDP、扩展接管） | 直接驱动，**复用同一个浏览器配置/任务空间** | 登录 1 次（约 40–120 秒） | 会话还在时通常 0 |
| T2 | 能读屏，但只能操作系统默认浏览器 | 用默认浏览器打开，用户点，Agent 读屏核对 | 登录 1 次 + 逐步确认 | 视会话 |
| T3 | 没有浏览器能力 | 用户自己操作，Agent 只给步骤和判断 | 最慢，但可用 | 视会话 |

**不要做**：要求用户安装 Chrome 或插件；问"你用哪个浏览器"；把 T3 说成"不支持"。用户的环境不应该为了这个技能而改变。

## 二、先查登录态，再决定要不要交接

用户电脑上往往早就登录过运营商商城。开工前先花一次读取确认，能省掉整段登录 + 短信：

1. 打开该运营商的官方入口（见下表）。
2. 读一次页面：
   - 出现脱敏号码 → 已登录；
   - 跳到登录页 → 未登录；
   - `0` / 空列表 / "加载中" → 只是没加载完，不是未登录，也不是余额 0。
3. 已登录且号码与用户给的一致 → **直接进业务，不要走登录交接**。

## 三、官方入口与未登录特征

| 运营商 | 入口 | 未登录的表现 |
|---|---|---|
| 移动 | <https://jf.10086.cn> | 页面出现"登录"入口，没有脱敏号码 |
| 联通 | <https://img.client.10010.com/jifenshangchengpc/index.html> | 账户区显示登录入口；积分显示 0 或"通讯积分不足" |
| 电信 | <https://apps.telefen.com/jycalls/?channelCode=HGOKHD> | 跳转 `m.telefen.com/MobileSSOv2/Login.aspx` |

这三条都是"入口级"判断，用来决定要不要交接；登录成功后的账户核对仍按入口 `SKILL.md` 第五节执行。

## 四、登录入口：让站点带你过去，不要自己拼

目标页优先仍然是默认路径，因为只有它能回答"你是不是已经登录了"。

1. **先开目标页。** 未登录时，站点会自己 302 到登录页（电信），或者页面上有"登录"入口（联通、移动）。
2. **需要登录时，点一次页面上的"登录"。** 这是站点自己的跳转，返回地址和渠道参数都是对的。如果它开的是新标签页，接管那个新页，不要再导航第三个地址。
3. **不要手工拼登录 URL。** 三家的登录地址都带 `appcode` / `goBack` / `service` 之类的参数，拼错会出现"登录成功但回到首页"或落到别的站点。确实要用地址，就用站点跳转后的当前地址，不要从文档里抄。
4. **已经是登录页就直接交接。** 不要再读一次确认"这确实是登录页"——那要多一轮。
5. **不要为了找登录入口再导航一次。** 地址变了但页面没白屏重载，那是 SPA 路由，本来就不花时间；只有出现新的 document 请求才算多了一次导航。怀疑多跳时，在 Network 面板过滤 `Document`：1 个是正常跳转，2 个才是多导航。

> 反例：先开主页 → 读一次 → 发现没登录 → 再导航到登录页。
> 代价是多一次渲染 + 一轮读取（约 3–10 秒），还可能丢掉登录后的返回地址。

## 五、用系统默认浏览器打开（T2 / T3）

| 系统 | 命令 |
|---|---|
| macOS | `open URL`（走默认浏览器） |
| Linux | `xdg-open URL` |
| Windows | `start "" "URL"`（cmd）或 `Start-Process "URL"`（PowerShell） |

`open` / `xdg-open` / `start` 只负责"打开"，不等于能控制。打开后由用户操作，Agent 只做读屏和核对。

## 六、宿主能驱动，但和用户默认浏览器不是同一个

按这个顺序决定，不要问用户：

1. 宿主的浏览器**已经有登录态**（或能复用上次的配置）→ 用它，直接查登录态。
2. 宿主的浏览器是全新的 → 仍然用它，但要告诉用户"这是 Agent 用的浏览器，第一次需要登录，之后会记住"。
3. 用户明确说"用我平时的浏览器，我已经登录了" → 走 T2/T3，让用户操作，Agent 读屏核对，不要试图接管他已开的标签页。

**不要**为了复用登录态去复制用户的浏览器配置目录、导出 Cookie 或读取本地凭据。这些做法会碰到用户的其他账号，收益也远小于风险。

## 七、做不到自动化时怎么说

一句话说清限制和替代，不要默默失败：

> 这台环境没法直接操作你的浏览器。你有两个选择：① 用我这里的浏览器打开，第一次登录一下，之后会记住；② 你自己在默认浏览器里打开这个链接，我来告诉你怎么点、帮你核对每一步。

## 八、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 新起的浏览器调试端口连不上 | 用户已经开着同一个浏览器，新进程只是转交标签页 | 不要反复重试；改用宿主自带浏览器 |
| Safari 无法被驱动 | 多数宿主只支持 Chromium 内核或自带引擎 | 直接走 T2/T3，不要让用户换浏览器 |
| 刚打开就显示未登录 / 积分 0 | 页面还没加载完 | 等业务信号，再读一次 |
| 用户说"我就是默认浏览器" | 浏览器已开着，Agent 接管不了 | 走 T3，由用户操作 |
| 登录成功后落在商城首页而不是话费/积分页 | 手工拼了登录 URL，丢了 `goBack` / `service` 返回参数 | 回到目标页再点一次；下次让站点自己跳 |
